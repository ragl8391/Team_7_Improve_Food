## Final Status Report

### What We Completed
- Completed a working MVP including:
  - Restaurant food listing form 
  - MongoDB database integration
  - Dynamic marketplace populated from the database
  - Session-based shopping cart
  - Checkout flow
  - Delivery radius validation
  - Order confirmation page

### What We Were in the Middle of Implementing
- Expanding checkout process to support both pickup and delivery
  - Integrating browser geolocation
  - Validating whether a customer was within a restaurant's delivery radius
  - Refining the checkout confirmation workflow
- Improving navigation between pages
- Addressing deployment-specific routing issues encountered when hosting the application through the Jupyter proxy environment

### What We Planned for the Future
- User authentication for both restaurants and customers
- Restaurant dashboards for managing listings and inventory
- Persistent order storage and order history
- Real-time inventory updates after purchases
- Secure online payment processing
- Support for multiple restaurant locations with dynamic delivery radii
- Notifications or email confirmations for completed orders
- Improved search, filtering, and recommendation features
- Interactive maps for restaurant locations and delivery coverage

### Known Problems and Limitations
- Navigation was affected by routing issues when deployed through the Jupyter proxy environment, requiring manual URL navigation during demonstration.
- Checkout currently generates an order confirmation but does not permanently store completed orders in the database.
- Restaurant locations and delivery radius calculations currently use placeholder data rather than restaurant-specific coordinates.
- Delivery availability is limited to a simple radius check and does not account for multiple restaurants or route optimization.
- The application does not currently support user accounts, authentication, payment processing, or inventory synchronization across multiple users. 
- The shopping cart is stored in the user's session and is not persistent across devices or browser sessions.

## System Overview

The system was designed around a modular three-tier architecture to separate the user interface, application logic, and data storage, making the application easier to develop, maintain, and extend.

Improve Food uses a standard three-tier architecture:
- Frontend: HTML, CSS, Javascript
- Backend: Flask
- Database: MongoDB
